## 프로젝트에서 직접 다룬 기술 문제

1. **서로 다른 영상·레이블을 모델 입력으로 정리하기:** CT 출혈 데이터셋은 영상 메타데이터와 레이블 값이 서로 달랐고, MRI는 DWI·ADC를 함께 입력해야 했습니다. 데이터별 방향·간격·레이블을 확인하고 각 모델의 입력 기준에 맞추는 작업이 필요했습니다.
2. **작은 병변의 실패를 평균 점수에 묻히지 않게 평가하기:** 큰 병변의 성능이 좋아도 작은 병변을 놓칠 수 있었습니다. Dice만으로 모델을 판단하지 않고 Recall, 검출 여부, 병변 크기별 결과를 함께 확인했습니다.
3. **학습 결과를 실제 분석 화면까지 전달하기:** 모델 출력만으로는 의료진이 결과를 조회할 수 없습니다. 영상 종류별 추론 입력과 결과 형식을 정의하고 FastAPI·Django·Celery·GCS를 거쳐 뷰어에 마스크와 부가 정보를 전달하는 흐름을 연결했습니다.

## 제가 맡은 작업

### 데이터 검증과 전처리

- CT 데이터의 방향, voxel spacing, affine 및 레이블 값을 점검하고 이진 출혈 마스크 기준을 정리했습니다.
- 데이터셋 간 형식 차이와 작은 병변 사례를 확인해 전처리 및 평가 과정에 반영했습니다.

### 모델 실험과 평가

- nnU-Net과 SegResNet을 바탕으로 손실 함수, 샘플링, 입력 구조를 비교했습니다.
- Dice, Recall, Precision과 병변 크기별 결과를 함께 살펴 실패 양상을 분석했습니다.
- 모델 선택을 단일 평균 점수로 단순화하지 않고 병변 검출과 오류 유형을 함께 검토했습니다.

### 추론 서비스와 결과 연동

- 영상 종류별 추론을 위한 공통 입출력 계약과 모델 로딩 구조를 작업했습니다.
- FastAPI 추론 API를 Django·Celery 분석 요청 및 GCS 저장 흐름에 연결했습니다.
- 의료진 뷰어에서 병변 마스크, 확률 맵, XAI 및 병변 정보를 조회할 수 있도록 결과 연동에 참여했습니다.
- MLflow Tracking·Registry의 모델 메타데이터를 관리자 화면에서 조회·동기화하는 흐름을 구현했습니다.

## 대표 기술 사례: CT 출혈 분할

### 데이터 품질 검증

BHSD와 CT-ICH처럼 출처가 다른 CT·마스크를 결합할 때 단순히 파일 수만 맞추지 않았습니다. 원본을 보존한 상태에서 CT와 마스크의 1:1 대응, NIfTI의 shape·spacing·qform/sform·effective affine, 강도 스케일링, 레이블 값과 빈 마스크를 확인했습니다. 예외 사례는 자동 교정으로 넘기지 않고 영상과 마스크를 겹쳐 보며 판단 근거를 기록했습니다. 전처리 후에는 shape·affine·이진 레이블·병변 부피 보존 여부를 다시 검사했습니다.

nnU-Net에는 원본 spacing을 가능한 한 유지하는 입력을, SegResNet에는 별도의 공통 전처리 입력을 준비했습니다. 두 모델의 결과를 비교할 때 입력 생성 방식도 함께 확인해야 하기 때문입니다.

### 실험에서 무엇을 바꿨는가

| 비교 예시 | 설정 | 확인하려 한 점 |
| :--- | :--- | :--- |
| **H-N00** 기준선 | nnU-Net, Dice+CE, foreground oversampling 0.33 | 기본 분할 성능과 병변 검출 수준 |
| **H-N80** 변형 | nnU-Net, Tversky+CE (α 0.3, β 0.7) | 놓친 병변을 더 강하게 벌점화했을 때 Recall과 오탐이 어떻게 달라지는지 |

이 비교는 손실 함수뿐 아니라 학습 epoch 설정도 다르므로, 점수 차이를 **손실 함수만의 효과**로 단정하지 않습니다. 실험별 설정과 데이터 분할을 함께 기록하고, 작은 병변에서 Recall이 나아지는지와 오탐이 늘어나는지를 같이 살펴봤습니다.

### 어떻게 평가했는가

- 양성 케이스의 foreground Dice 평균과 전체 voxel 수준 지표를 구분했습니다.
- 병변 단위 Recall·Precision·F1과 병변 크기별 결과를 확인해 작은 병변의 누락을 살펴봤습니다.
- 음성 케이스는 Dice 평균에 섞지 않고 오탐 여부와 FP/scan으로 별도 평가했습니다.
- threshold와 최소 병변 크기는 validation에서 정하고, test 결과를 보고 다시 맞추지 않는 기준을 사용했습니다.

이 문서에는 서로 다른 시점의 실험 수치를 섞어 단일 '최고 성능'으로 제시하지 않았습니다. 최종 모델과 고정된 평가 split이 확정되면 모델 ID, 데이터 범위, Dice·Recall·오탐을 같은 표에 넣어 비교할 수 있습니다.

## 서비스에 연결한 방식

모델 학습 코드는 서비스 코드와 분리했습니다. 추론 단계에서는 입력 영상의 종류와 모델 버전을 식별하고, FastAPI가 모델을 로드해 결과를 생성하는 흐름을 작업했습니다. Django·Celery의 분석 요청과 GCS의 모델·결과 저장 경로를 연결하고, 의료진 뷰어가 영상 위에 마스크·확률 맵·XAI 결과를 표시할 수 있도록 응답 구조를 맞췄습니다. MLflow에서는 실험과 모델 메타데이터를 관리하고 관리자 화면에서 동기화하도록 연결했습니다.

| :--- | :--- |
